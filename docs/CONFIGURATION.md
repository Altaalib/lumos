# Настройка перед первым запуском

Это самый важный документ: без значений из этого списка ни один из
трёх сервисов не запустится. Всё настраивается через `.env` в корне
репозитория — скопировать `.env.example` в `.env` и заполнить.

```
cp .env.example .env
```

Дальше по каждому пункту — что это, где взять, что будет, если не
заполнить.

## 1. DATABASE_URL

Строка подключения к PostgreSQL. Для локальной разработки через
`docker-compose.yml` из корня репозитория ничего менять не нужно —
значение в `.env.example` уже соответствует пользователю/паролю/базе,
которые создаёт `make up`.

Если Postgres свой (не через `make up`) — подставить реальные
хост/порт/пользователя/пароль/базу:

```
DATABASE_URL=postgres://USER:PASSWORD@HOST:5432/DBNAME?sslmode=disable
```

Без этой переменной ни один из трёх сервисов не стартует.

## 2. Reader — доступ к Telegram API (MTProto)

Reader читает каналы под учётной записью обычного пользователя
Telegram (не бота — публичные каналы, куда бот не добавлен как админ,
через Bot API не почитать).

- **TG_APP_ID**, **TG_APP_HASH** — получить на
  [my.telegram.org](https://my.telegram.org) → **API development
  tools** → создать приложение (можно указать любое название и любую
  платформу, это не имеет значения для работы сервиса). После создания
  на странице будут `App api_id` и `App api_hash`.
- **TG_PHONE** — номер телефона аккаунта, под которым авторизуется
  reader, в международном формате: `+79991234567`.
- **TG_PASSWORD** — только если на аккаунте включена двухфакторная
  аутентификация (облачный пароль). Если нет — оставить пустым.
- **TG_CHANNELS** — список username каналов через запятую, с `@` или
  без — без разницы: `TG_CHANNELS=meduzalive,tjournal`.

При первом запуске `./bin/reader` (или `make run-reader`) попросит
код подтверждения прямо в терминале — Telegram пришлёт его в
приложение или SMS на номер из `TG_PHONE`. Это разовое действие: после
успешного входа сессия сохраняется в файл `TG_SESSION_FILE`
(по умолчанию `lumos-reader.session.json` в рабочей директории) —
дальнейшие перезапуски проходят без интерактива. Файл сессии — это
токен доступа к аккаунту Telegram, он никогда не должен попадать в git
(уже в `.gitignore`) и не должен передаваться никому.

## 3. Analyzer — доступ к LLM

- **LLM_API_KEY** — ключ провайдера. По умолчанию сервис обращается к
  OpenAI (`LLM_BASE_URL=https://api.openai.com/v1`,
  `LLM_MODEL=gpt-4o-mini`) — ключ берётся в
  [platform.openai.com/api-keys](https://platform.openai.com/api-keys).
- Если нужен другой провайдер — меняются **LLM_BASE_URL** и
  **LLM_MODEL**, код трогать не нужно (см. `docs/DEPENDENCIES.md`,
  раздел про LLM-клиент, там же список проверенных альтернатив —
  OpenRouter, DeepSeek, локальный Ollama/vLLM).

Без **LLM_API_KEY** analyzer не запустится.

## 4. Notifier — бот и чат для уведомлений

- **TELEGRAM_BOT_TOKEN** — создать бота через
  [@BotFather](https://t.me/BotFather) командой `/newbot`, токен придёт
  в чате с ним.
- **TELEGRAM_CHAT_ID** — куда слать уведомления. Для личных
  уведомлений — свой личный chat ID: написать что угодно любому боту
  вроде [@userinfobot](https://t.me/userinfobot), он пришлёт `Id`. Это
  число (может быть отрицательным для групп) и есть
  `TELEGRAM_CHAT_ID`.
- Важно: бот должен получить от вас хотя бы одно сообщение до первой
  отправки — Telegram не позволяет боту писать первым пользователю,
  который никогда не начинал с ним диалог. Проще всего — просто
  открыть чат с созданным ботом и отправить `/start`.

## 5. criteria.txt

Не переменная окружения, а отдельный файл в корне репозитория — по
нему LLM решает, важен пост или нет. Свободный текст на естественном
языке, пример уже лежит в репозитории и подходит для первого запуска.
Редактируется в любой момент без пересборки и рестарта — analyzer
перечитывает файл на каждом цикле.

## Чек-лист первого запуска

1. `cp .env.example .env`
2. Заполнить `DATABASE_URL` (или оставить дефолт под `make up`)
3. Заполнить `TG_APP_ID`, `TG_APP_HASH`, `TG_PHONE`, `TG_CHANNELS`
4. Заполнить `LLM_API_KEY`
5. Заполнить `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`
6. Проверить/отредактировать `criteria.txt`
7. `make up && make migrate-up`
8. `go mod tidy && make build`
9. Запустить `./bin/reader` первым и отдельно — ввести код
   подтверждения, дождаться сообщения о сохранении сессии, затем можно
   останавливать и запускать в фоне вместе с остальными двумя
